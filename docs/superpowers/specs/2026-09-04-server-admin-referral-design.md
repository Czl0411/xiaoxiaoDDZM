# DZMMBot 服务器管理后台与传送门奖励设计

## 目标

将现有桌面机器人改造成可在 Ubuntu 4 核 4 GB 服务器长期运行的项目，同时保留现有业务数据和 Socket.IO 消息通道。管理员通过带登录验证的网页后台管理机器人，并能在后台中操作服务器上的 Chromium 完成 aikda 登录。新增“传送门拉新”奖励：新人通过成员邀请链接进群后，累计发送 3 条群消息时，仅结算一次邀请奖励。

首个部署目标为 `124.223.175.168`。没有域名，第一阶段使用服务器 IP 访问；不设置客户端 IP 白名单。VNC、应用内部端口和数据库不得直接暴露到公网。

## 范围

本次包含：

- 正式的网页后台登录、会话和退出登录。
- Ubuntu 标准目录、systemd 服务、Nginx 入口、部署与回滚脚本。
- 服务器 Chromium、虚拟显示和仅限已登录管理员使用的浏览器控制页面。
- 保持 `python-socketio.AsyncClient` 作为消息读取和发送通道。
- 当前 SQLite 数据库、配置、图库、图片生成文件和密钥的迁移。
- 传送门来源追踪、3 条发言门槛、奖励结算、好感度和播报。
- 后台运行状态、连接状态、拉新进度与记录。

本次不包含：

- PostgreSQL 迁移或多机集群。
- 多管理员角色和复杂权限系统。
- 公网开放原始 VNC/noVNC 端口。
- 域名和受信任公网 TLS 证书。
- 修改只读参考项目 DDZM。

## 总体架构

部署保持单仓库和单数据源，拆成三个受 systemd 管理的进程：

1. `dzmmbot.service`：机器人调度、Socket.IO 连接、命令处理、定时任务和奖励结算。
2. `dzmmbot-web.service`：FastAPI 管理后台、登录鉴权和管理 API。
3. `dzmmbot-browser.service`：在 Xvfb 虚拟显示中运行持久化 Chromium，并通过仅监听回环地址的 noVNC/websockify 提供画面。

Nginx 是唯一公网入口。它把后台网页和 API 转发到回环地址上的管理服务，并把后台内嵌的浏览器控制路径转发到 noVNC。机器人和后台共享 `/var/lib/dzmmbot/data/bot.db`。SQLite 开启 WAL 和 busy timeout；写操作维持短事务。当前规模只运行一个机器人写入者，因此不引入额外数据库服务。

## 目录与服务账户

- `/opt/dzmmbot/releases/<revision>`：不可变版本目录。
- `/opt/dzmmbot/current`：指向当前版本的符号链接。
- `/opt/dzmmbot/venv`：Python 虚拟环境。
- `/var/lib/dzmmbot/data`：数据库、配置、图库和浏览器资料。
- `/var/log/dzmmbot`：应用日志目录。
- `/etc/dzmmbot/dzmmbot.env`：权限 `0600` 的服务器环境变量。

服务以无登录权限的 `dzmmbot` 系统用户运行，不以 `root` 或 SSH 用户运行。部署脚本只在安装依赖、替换版本链接和重启服务时使用提权。

## 网页后台认证

首次部署通过环境变量设置单一管理员用户名和密码哈希，明文密码不进入仓库、数据库或日志。登录成功后发放随机服务端会话，Cookie 使用 `HttpOnly`、`SameSite=Strict` 和有限有效期；在没有 HTTPS 的第一阶段不能设置 `Secure`。所有修改类请求需要登录并验证 CSRF 令牌，登录接口需要节流和失败延迟。

Nginx 只开放后台入口端口；机器人 API、noVNC、Xvfb 和数据库保持回环或本地访问。后台的浏览器控制页通过同一登录会话授权后才反向代理，不能通过另一个公网端口绕过登录。

因为第一阶段使用公网 HTTP，后台会显示安全警告。后续添加域名时只需配置 Nginx TLS 和 `Secure` Cookie，不改业务代码。

## 服务器浏览器与 Socket.IO

Chromium 使用 `/var/lib/dzmmbot/data/browser_profile` 作为持久化配置目录，在 Xvfb 中以有界资源参数运行。管理员在后台“浏览器登录”页面操作实际 Chromium；登录状态保存在服务器，不需要把本地浏览器配置上传到 Git。

浏览器职责限定为：

- 首次登录或登录失效时供管理员操作。
- 提供 Socket.IO 所需的登录用户资料、访问令牌和 Cookie。
- 上传图片时执行现有站点认证流程中确实需要浏览器身份的部分。

消息接收、文本发送和图片消息发送继续使用 `python-socketio.AsyncClient`，不恢复 DOM 轮询或 DOM 发消息。后台展示连接状态、账号、监听房间、最后收发时间、错误和重连次数，并提供受保护的重连与服务重启操作。

## 传送门来源追踪

站点入群系统消息格式为：

`{新人昵称} 通过 {邀请人昵称} 的链接加入了群聊`

Socket.IO 规范化层新增对系统消息类型的只读解析，并尽可能保留载荷中的新人和邀请人稳定 ID。如果载荷只有昵称，则建立一条当前群的待绑定记录：新人第一次发送普通群消息时，按当前昵称绑定其稳定用户 ID；邀请人按当前称呼、当前昵称和昵称历史查找，只有唯一匹配时才绑定。歧义或查无此人时不猜测，保存失败原因供管理员处理。

每条来源记录包括群、邀请人、新人、系统消息 ID、入群时间、入群后的有效发言数、状态和结算时间。系统消息 ID及“群 + 新人稳定 ID”均设唯一约束，防止重连和历史回放造成重复记录。

## 发言门槛与一次性结算

有效发言定义为新人在来源群、入群时间之后发送的非系统、非机器人消息。文字、图片和指令都计数。每个稳定 `message_id` 最多计数一次。

第 1、2 条消息只更新进度。第 3 条消息在一个数据库事务中完成：

1. 锁定或条件更新仍为待奖励的来源记录。
2. 给邀请人增加当前配置的功德。
3. 给邀请人的 `saintess_affection` 增加 1。
4. 写入功德流水和拉新结算记录。
5. 将来源记录标记为已奖励。

只有事务成功提交后才发送群播报。发送失败不回滚奖励；播报进入可重试通知状态，避免重试时二次发钱。

拒绝自己邀请自己。机器人重启、相同消息重复投递、昵称变化以及重复入群系统消息均不得产生第二次奖励。

## 配置、命令与展示

默认奖励为 40 功德，配置键为 `features.referral_reward_amount`。管理员命令：

`/设置拉新奖励 40`

仅管理员可执行，允许范围 `0` 到 `100000`。设置为 0 时仍增加好感度并播报 0 功德。后台提供同一设置项并显示最后修改时间。

用户 `/我` 增加：

`圣女好感度：{数值}`

达标播报使用结算时的当前称呼和实际奖励：

```text
迷途的羔羊 {新人ID} 顺着 {邀请人ID} 的传送门来到了大教堂，并成功进行了祈福。
圣女对 {邀请人ID} 好感度 +1，并发放了 {奖励功德} 功德奖励。
提示：主页挂上传送门，方便接引更多迷途的羔羊进来洗礼，为你提供源源不断的功德。
```

这里的 `ID` 按现有机器人文案习惯显示成员当前称呼，而数据库始终使用平台稳定用户 ID 关联。

## 后台页面

后台沿用现有页面和 API，新增：

- 登录页与退出登录。
- 运行总览：服务状态、登录状态、Socket.IO 状态和最后收发时间。
- 浏览器登录：在受保护页面内控制服务器 Chromium。
- 拉新管理：奖励值、待绑定、1/3 或 2/3 进度、已成功、失败原因和流水链接。

所有会改变余额、好感度、配置或服务状态的后台操作写审计记录。页面不得显示完整 API Key、Cookie 或访问令牌。

## 数据迁移与发布

首次迁移使用现有导出脚本生成 SQLite 在线快照和资源白名单包，再通过加密 SSH 通道上传到临时目录。服务器在校验文件后安装到 `/var/lib/dzmmbot/data`。不上传本地日志和浏览器历史；API Key 进入服务器权限受限的数据或环境文件，不进入 Git。

发布采用版本目录和原子符号链接：上传新版本、安装依赖、运行迁移和测试，成功后切换 `current` 并重启。失败时恢复旧链接和服务。数据变更通过向前兼容的 SQLite 建表/加列完成；部署前保留数据库快照。

切换前暂停本地机器人，避免两个实例同时监听并回复。服务器验证通过后，本地实例保持停止。

## 验证与验收

自动测试覆盖：

- 系统入群消息解析及普通消息不误判。
- 首次发言绑定稳定 ID，昵称歧义时拒绝猜测。
- 第 1、2 条不奖励，第 3 条只结算一次。
- 重复消息、重启、重复系统事件和并发处理不重复奖励。
- 自邀拒绝、奖励为 0、配置持久化和管理员权限。
- `/我` 好感度展示和播报变量。
- 未登录后台拒绝访问，登录、退出、CSRF 和浏览器控制代理授权。

服务器验收顺序：

1. systemd 三项服务健康且仅 Nginx 对公网开放。
2. 网页登录、退出和未授权拦截有效。
3. 后台中可以看到并操作 Chromium，aikda 登录状态可持久化。
4. Socket.IO 能读取真实群消息并发送测试回复，DOM 不参与消息收发。
5. 当前数据库、配置和图库数量与迁移清单一致。
6. 用测试邀请记录验证 1/3、2/3、结算、功德流水、好感度和群播报。

## 安全与已知限制

公网 HTTP 无法防止链路窃听，第一阶段只作为临时状态；后台必须使用独立强密码，且不得复用 SSH 密码。建议后续增加域名和受信任 HTTPS，或恢复固定客户端 IP 白名单。

如果 aikda 的系统消息载荷没有稳定 ID，首次发言前只能按昵称保存待绑定记录；同群同名会进入人工检查而不是自动奖励。这是避免错发奖励的必要限制。
